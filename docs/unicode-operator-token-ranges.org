#+TITLE: The Unicode Operator Token Set, as Ranges
#+SUBTITLE: The 32 allowed ranges, and every code point in the blocks that is not one
#+AUTHOR: Steve Downey
#+options: toc:nil num:t ^:nil ':nil

The frozen operator token set of P4345 ([[file:unicode-operators.md][the design doc]], /token-set/): a
code point is a user-operator token iff it is Pattern_Syntax, non-ASCII,
inside the nine mathematical/arrow blocks, of General_Category Sm or So, and
not on the named exclusion list. The predicates were applied *once*, against
UCD 17.0.0, and the result is frozen by enumeration — these tables do not
track later Unicode versions.

Derived by =docs/pattern-syntax-audit.py= from the five UCD 17.0.0 inputs
pinned in =docs/ucd-17.0.0.sha256= (all five verified against the manifest
before derivation). The allowed table below is byte-for-byte the
=UserOperatorRanges[]= table the generator emits into
=clang/lib/Lex/UnicodeOperatorCharSets.h= on the Unicode branches.

The two tables partition the blocks exactly: 1,381 allowed + 75 rejected
= 1,456 code points, the full span of the nine blocks. The one named
exclusion *outside* the blocks, U+2044 ⁄ FRACTION SLASH (reads as ~/~), does
not appear below: it already fails the block predicate, and is kept on the
exclusion list only so that list reads as the confusability audit's complete
output.

design's, in the order a reader meets them in the derivation: the named

By class: 12 confusables (the 13th, U+2044, is outside the blocks), 3
identifier-profile characters — exactly Pattern_Syntax ∩ ID_Compat_Math, the
three the design cedes to the identifier side — 12 emoji-presentation
carve-outs, 46 paired brackets (23 open/close pairs, worth keeping unspent
for any future bracketing proposal), and the 2 code points Pattern_Syntax
reserves but UCD 17.0 leaves unassigned. The confusables are *rejected, not
aliased*: a program containing a character that looks like ~-~ but is not
must fail to lex, not quietly mean something else.
