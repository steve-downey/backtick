* The proposal

Declare it —

#+begin_src c++
Vec operator⊞(Vec const& a, Vec const& b);
#+end_src

write it —

#+begin_src c++
a ⊞ b
#+end_src

- Operators drawn from [[https://www.unicode.org/reports/tr25/][UTR #25]],
  /Unicode Support for Mathematics/ — frozen by the paper, confusables
  removed.
- Otherwise ordinary functions: ordinary lookup, ordinary overload
  resolution.

* The token set

- Pattern_Syntax, non-ASCII, in nine math and arrow blocks, ~gc~ ~Sm~ or
  ~So~, minus a named exclusion list.
- Applied once, against UCD 17.0.0. Frozen by enumeration — the table does
  not track later Unicode versions.
- 1,381 code points, 32 contiguous ranges. Plus 75 rejected: the blocks
  partition exactly.

** What came out

- Confusables, multi-character: ⇐ ⇒ ⇔ ≤ ≥ read as ~<=~ ~=>~ ~<=>~ ~<=~ ~>=~.
- Confusables, single: − ∕ ∗ ∙ ⋅ ∶ ∣ read as ~-~ ~/~ ~*~ ~.~ ~.~ ~:~ ~|~.
- Identifier characters, by TR31 §7.1: ∂ ∇ ∞.
- Paired brackets, ~gc Ps~ and ~gc Pe~: ⌈ ⌉ ⟦ ⟧ ⟨ ⟩ — delimiters.
- Emoji presentation, by the TR31 §7.2 carve-out: ⌚ ⏰ ⏳.

* It looks like this

#+begin_src c++
constexpr int operator⊞(int a, int b) { return a + b; }
static_assert(5 ⊞ 7 == 12);

Matrix operator⊗(Matrix const&, Matrix const&);
a ⊗ b ⊗ c                    // operator⊗(operator⊗(a, b), c)

Vec operator⊖(Vec const&);   // one parameter: unary prefix
⊖v                           // operator⊖(v)
#+end_src

* Order of interpretation

#+ATTR_REVEAL: :frag (appear)
- Tokens, then parse, then lookup. In that order. Always.
- The parser identifies an operator with *no knowledge of any declaration*.
- So the set is fixed by the grammar — a frozen enumeration.
- Meaning arrives later, at overload resolution — like ~operator+~ on a
  class type.
- Julia: fixed parse table, user-defined meanings. Not Swift's
  declaration-gated parse.

** Position decides

#+transclude: [[file:unicode-operator-parse-hazards.org::08bc53d9-d490-46f7-bc42-cbeba7739317]]  :lines 2- :end "08bc53d9-d490-46f7-bc42-cbeba7739317 end"

- ~^~ marks the column where the parse commits, or where it breaks.
- Operand position → prefix. After a complete operand → infix. No postfix.
- Nothing else consulted: not whitespace, not declarations, not the next
  token.

* The fixity problem

#+ATTR_REVEAL: :frag (appear)
- A declared precedence must *travel with the name* — headers, modules, TUs.
- The parse of ~a ⊕ b ⊗ c~ comes to depend on which imports are visible.
- Two TUs disagreeing about the grouping: an ODR / IFNDR factory.
- A precedence *is* a meaning: ⊗ is multiplication-like in tensor algebra,
  backwards in a tropical semiring.

* ~clang-format~ must work

#+ATTR_REVEAL: :frag (appear)
- Formats code it has not compiled: no Sema, no lookup, no imports.
- Still has to answer /how does this group?/
- Prototype: the query answered ~prec::Unknown~; chains wrapped wrongly;
  *every spacing and annotation test passed*.
- Teaching it these rules took about forty lines.
- A table it can consult. A declaration it cannot.

* The misparse

#+ATTR_REVEAL: :frag (appear)
- Postfix was prototyped: after a complete operand, look ahead one token —
  "can it begin a cast-expression?" → infix; otherwise postfix.
- The witness set contains surprises.

* More ways to go wrong

** Maximal munch

#+transclude: [[file:unicode-operator-parse-hazards.org::d49fbfc6-a346-4b6a-83fb-6c38f31aa06e]]  :lines 2- :end "d49fbfc6-a346-4b6a-83fb-6c38f31aa06e end"

- Lexing precedes lookup: no declaration can split, or fuse, a token.
- No user ~&&&~, ever. No operator is a prefix of another.

** Whitespace fixity — the Swift rule

#+transclude: [[file:unicode-operator-parse-hazards.org::f3dc6082-dcd8-494b-a26a-ee92b89f0c49]]  :lines 2- :end "f3dc6082-dcd8-494b-a26a-ee92b89f0c49 end"

- ~<~ marks one the rule must examine /behind/ it. So ~<^>~ is a column of
  lookback and a column of lookahead, at every use.

** The one true ambiguity

#+transclude: [[file:unicode-operator-parse-hazards.org::d09108ee-a9c2-43d0-99e2-4aa6c7536a96]]  :lines 2- :end "d09108ee-a9c2-43d0-99e2-4aa6c7536a96 end"

- The resolutions on offer: whitespace sensitivity, or a
  declaration-dependent parse. Both declined — the operator set and the
  identifier set stay disjoint.

* Position decides

- The parse of every expression is a function of the expression alone.
- Only the /meaning/ of ~operator⊞~ travels — by ordinary lookup, which
  already knows how to travel.
- ~^~ only: no lookahead, no lookback, no whitespace, no declarations.
