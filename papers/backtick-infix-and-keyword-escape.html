13.1. [lex.operators]source

Modify the operator-or-punctuator grammar in [lex.operators] paragraph 1 by adding `: 

operator-or-punctuator: one of
    ...
    ?     ::    .     .*    ->    ->*   ^^    ~     `
    ...

The row shown is [lex.operators]'s third; only the trailing ` is added.

13.2. [lex.name]source

Add to [lex.name], after the paragraphs defining identifier: 

escaped-identifier:
    ` identifier `

An escaped-identifier may appear wherever the grammar uses identifier. The token between the ` tokens is treated as an identifier even if it would otherwise be a keyword or alternative token. The ` tokens are not part of the identifier. An escaped-identifier and an unescaped identifier with the same spelling are the same identifier. 

void `new`();          // declares a function named new
`new`();               // and calls it
int `count` = 0;
++count;               // names the same object

13.4. [expr.backtick] (new subclause)source

Annex A ([gram]) is updated mechanically to match.

Insert a new subclause between [expr.cast] and [expr.mptr.oper]:

Backtick operator [expr.backtick]source

user-infix-expression:
    cast-expression
    user-infix-expression ` backtick-operator ` cast-expression

backtick-operator:
    assignment-expression
    simple-type-specifier
    typename-specifier

An expression of the form E1 `O` E2 is identical (by definition) to O(E1, E2) ([expr.call]).

If the backtick-operator is a simple-type-specifier or typename-specifier denoting a type T or a placeholder for a deduced class type, an expression of the form E1 `T` E2 is identical (by definition) to T(E1, E2) ([expr.type.conv]). A backtick-operator whose tokens can be interpreted both as an assignment-expression and as a simple-type-specifier or typename-specifier is interpreted as a simple-type-specifier or typename-specifier.

When parsing a backtick-operator, the first non-nested `1 is taken as the ending delimiter, rather than as the first delimiter of a nested user-infix-expression.
