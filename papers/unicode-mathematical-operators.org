* Abstract
I propose adding the ability to declare user defined operators, such as operator⊞ , allowing users to write ~a ⊞ b~. The list of allowed operators is drawn from the mathematical operators described in Unicode Technical Report #25, /Unicode Support for Mathematics/ [cite:@UTR25], with confusables removed. The operators are otherwise normal functions, found by ordinary lookup rules and ordinary overload resolution.

#+begin_src c++
constexpr int operator⊞(int a, int b) { return a + b; }
static_assert(5 ⊞ 7 == 12);

Matrix operator⊗(Matrix const&, Matrix const&);
a ⊗ b ⊗ c                               // operator⊗(operator⊗(a, b), c)

Vec operator⊖(Vec const&);              // one parameter: unary prefix
⊖v                                      // operator⊖(v)
#+end_src

concrete; it is not offered as final CWG wording. Wording is relative to the
current working draft.

** [lex.operators]

Add /user-operator/ as an alternative of /operator-or-punctuator/ in
{{{sref(lex.operators)}}}:

#+begin_addedblock
#+begin_quote
#+begin_verse
user-operator:
    one of the characters in Table X, User-operator characters
#+end_verse
#+end_quote
#+end_addedblock

#+begin_note
Table X will contain the frozen enumeration of 1,381 code points described in
[[The token set]]. A /universal-character-name/ designating one of those
characters forms the same token by the existing translation rules.
#+end_note

** [over.unary] and [over.binary]

In {{{sref(over.unary)}}}, extend the definition of a prefix unary operator
function to include a function named by a /user-operator/ in the added
/unary-expression/ production. In {{{sref(over.binary)}}}, extend the
definition of a binary operator function to include a function named by a
/user-operator/ in a /user-infix-expression/. The existing transformations to
member and non-member function-call notation then apply unchanged.

Annex A ({{{sref(gram)}}}) is updated mechanically to match.
